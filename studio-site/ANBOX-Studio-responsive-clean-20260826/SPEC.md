# ANBOX Studio — спецификация объединения mobile + desktop

Статус: `branch/current`  
Область: комплект отдельных Tilda VibeBlock-секций ANBOX Studio  
Дата: 2026-08-26

## 1. Источники и приоритет

1. Текущий запрос пользователя: объединить последнюю mobile- и desktop-версии, не смешивая их визуальную реализацию; сохранить перенос отдельными блоками; очистить код без редизайна.
2. `Tilda_Vibe_Section_Spec.md`: два соседних визуальных корня, уникальные `id`, CSS-переключение на 640/641 px, корневое ограничение JavaScript, требования к media.
3. Mobile source: `ANBOX-Studio-mobile.html` от 2026-08-26.
4. Desktop source: `ANBOX-Studio-desktop-final-20260826.zip`; распакованная папка проверена по SHA-256 всех файлов и совпадает с архивом.
5. `design-system.md`, `STUDIO-ECOSYSTEM.md`, `DELIVERY-STANDARD.md` и требования mobile QA.

Исходники содержат разные композиции и тексты. Их контент не синхронизируется и не смешивается: на каждом диапазоне используется своя последняя версия.

## 2. Формат поставки

Комплект состоит из 11 визуальных VibeBlock-файлов и одного служебного блока:

1. `00-header.html`
2. `01-hero.html`
3. `02-approach.html`
4. `03A-portfolio-system.html` — служебные стили, вставляется перед визуальным портфолио;
5. `03B-portfolio.html`
6. `04-services.html`
7. `05-packages.html`
8. `06-clients.html`
9. `07-team-training.html`
10. `08-blog.html`
11. `09-contacts.html`
12. `10-footer.html`

Desktop- и mobile-разметка портфолио объединяются в одном `03B-portfolio.html`. Тяжёлый portfolio stylesheet остаётся в `03A-portfolio-system.html`, потому что полный блок превышает практический размер VibeBlock. `03A` является осознанным служебным блоком и не обязан показывать панель «Вайб-секция».

Кейсы в обеих версиях `03B` дополнительно получают последовательные маркеры `data-anbox-case="01"…"20"`. Они не меняют вид и дают стабильные точки поиска при обновлении конкретного кейса; отдельный скрытый JSON-каталог не создаётся, чтобы изображения и тексты оставались редактируемыми непосредственно в визуальном блоке.

## 3. Контракт каждого VibeBlock

- В файле находятся ровно два соседних верхнеуровневых визуальных элемента: desktop-root и mobile-root.
- Общего HTML-контейнера вокруг пары нет.
- `<style>` и `<script>` располагаются вне обоих визуальных корней.
- Desktop-root получает классы `anbox-desktop-part anbox-desktop-part--NN`.
- Mobile-root получает классы `anbox-mobile-part anbox-mobile-part--NN`.
- Все mobile `id` получают префикс `abm-`; связанные `href`, `for`, `aria-*`, CSS и JS обновляются согласованно.
- При `max-width: 640px` desktop-root скрыт, mobile-root отображается.
- При `min-width: 641px` mobile-root скрыт, desktop-root сохраняет исходный display.
- Переключающий CSS находится до визуальных корней, поэтому обе версии не показываются одновременно при загрузке.

Исключение: `03A-portfolio-system.html` не содержит визуальных корней и используется только вместе с непосредственно следующим `03B-portfolio.html`.

## 4. Изоляция дизайна

- Desktop-разметка, геометрия, контент и актуальный каскад берутся из desktop-final без визуального пересочинения.
- Mobile-разметка, геометрия, контент и runtime берутся из `ANBOX-Studio-mobile.html`.
- Mobile stylesheet активен только при `max-width: 640px` и ограничен `.anbox-mobile-part`, чтобы не менять внешние блоки страницы Tilda.
- Desktop stylesheet относится только к desktop-root своего блока; mobile-root использует единый mobile stylesheet из первого блока.
- ANBOX Display остаётся только у HERO H1. Все остальные заголовки, текст и UI используют Onest.
- Сохраняются рабочие purple/lime сигналы, поверхности, сетка, изображения, motion и `prefers-reduced-motion` fallback обеих последних версий.

## 5. Безопасная очистка

Разрешено:

- удалить архивные HTML/CSS-комментарии и служебные маркеры итераций;
- объединить последовательные desktop `<style>` в один актуальный stylesheet с сохранением порядка каскада;
- удалить повторные `@import` из секций и оставить единственное подключение Onest в общем слое `00-header.html`;
- удалить desktop media-ветки, применимые только до 640 px, потому что в этом диапазоне desktop-root всегда скрыт;
- удалить mobile media-ветки от 48rem, потому что mobile-root активен только до 640 px;
- удалить desktop-селекторы, которые относятся только к другим секциям и физически не могут совпасть внутри текущего корня;
- удалить повторяющиеся глобальные scroll-replay runtime-скрипты;
- ограничить runtime корнем версии и запускать его только в активном диапазоне;
- добавить `loading="lazy"` mobile-изображениям ниже видео-HERO.

Запрещено:

- смешивать desktop- и mobile-компоненты внутри одного визуального корня;
- переносить контент между версиями;
- менять тексты, цены, кейсы, изображения, композицию или motion ради унификации;
- нормализовать позднюю desktop 4K-систему к 1200 px без отдельного решения;
- самовольно нормализовать фактическую палитру последних исходников к Core-токенам; согласованное решение и итоговые роли зафиксированы в разделе 8.

## 6. JavaScript

- Desktop runtime запускается только при `min-width: 641px`.
- Mobile runtime запускается только при `max-width: 640px`.
- Повторная инициализация блокируется через `data-*Ready`/локальный флаг.
- Поиск элементов выполняется от корня конкретного блока; обращение к другому блоку допускается только для явной связи mobile HERO ↔ mobile header.
- Скрытая версия не запускает autoplay, таймеры, observers и обработчики компонентов.
- `prefers-reduced-motion` сохраняет статичный рабочий сценарий.

## 7. Media

- Значимые изображения остаются отдельными `<img>`.
- У каждого `<img>` обязательны `src`, `alt`, `width`, `height`.
- Только фактический desktop HERO LCP имеет `fetchpriority="high"`; остальные desktop-слайды загружаются лениво.
- Mobile HERO остаётся видео с `autoplay`, `muted`, `loop`, `playsinline`, `poster`, `aria-hidden="true"` и `preload="auto"`.
- Mobile-изображения ниже HERO получают `loading="lazy"`.
- Относительные assets поставляются рядом с блоками с сохранением путей.

## 8. Общие цветовые и wide-screen токены

Последняя реализация нормализуется к единой системе:

- `paper #F3F4F0`;
- `ink #151716`;
- `purple #AD95EE` для брендовых заливок и сигналов;
- `purple-strong #7658D0` для контрастного текста и focus;
- единый базовый `lime #DDE63F`;
- `1200px` остаётся desktop master, а подтверждённый fluid/4K profile до `3328px` с inset `clamp(20px, 6.667vw, 256px)` сохраняется для корректной композиции и проигрывания motion на 2K/4K.

## 9. Критерии приёмки

- 12 файлов идут в указанном порядке; `03A` всегда находится непосредственно перед `03B`.
- В каждом визуальном файле ровно два верхнеуровневых визуальных корня; `03A` является документированным служебным исключением.
- Нет повторяющихся `id` в общем preview.
- На 320, 360, 375, 390, 412 и 640 px видны только mobile-roots.
- На 641, 768, 1024, 1440, 1920 и 3840 px видны только desktop-roots.
- На 320 px нет page-level horizontal scroll.
- Mobile menu, approach carousel, services tabs, package tabs, portfolio reveal и form state работают.
- Desktop header, HERO slider, portfolio controls, services, packages, clients, team/blog reveals и contacts form запускаются без page errors.
- Все изображения проходят проверку обязательных атрибутов.
- CSS скрытой версии не влияет на computed styles активной версии.
- Визуальные контрольные снимки последней mobile- и desktop-версий не показывают регрессий, вызванных объединением.
- Итоговый preview имеет `lang`, viewport meta, title, description, reset внешних margin и `prefers-reduced-motion` поведение исходников.

## 10. Ограничение проверки Tilda

Условие появления панели «Вайб-секция» основано на внутреннем поведении редактора Tilda. Локально проверяется DOM-контракт из двух соседних корней; финальное появление панели и совпадение опубликованной страницы с редактором проверяются после вставки в Tilda.
