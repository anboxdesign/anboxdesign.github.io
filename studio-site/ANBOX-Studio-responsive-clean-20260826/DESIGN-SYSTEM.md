# ANBOX Studio Core Design System

Статус: `core/current`  
Область: основная дизайн-система студии и база для всех направлений

## Роль документа

Это корневой источник визуальной и интерфейсной логики ANBOX Studio. Направления наследуют его дисциплину, но могут создавать собственные цветовые и композиционные ветки.

Локальная презентационная система вынесена в `tilda-transfer-kit/AGENTS.md`, `tilda-transfer-kit/03-style-guide.md` и `tilda-transfer-kit/06-slide-master-reference-style.md`.

## Подтверждённые источники внутри workspace

- `study-redesign/11-studio-dna-motion-map.md` — зафиксированная веб-грамматика действующего проекта студии;
- `study-redesign/12-studio-course-reference-v2.md` — проверенное наследование сетки, шрифтов и шапки;
- `study-redesign/07-typography-audit.md` — точные шрифтовые файлы;
- `study-redesign/03-design-system-draft.md` — историческая фиксация core-пары `#AD95EE + #DDE63F` основного коммерческого сайта;
- `study-redesign/references/studio-course-direction-v2.html` — рабочая реализация сетки, adaptive и типографики в производной ветке.

Корневые `index.html`, `styles.css` и `script.js` относятся к раннему прототипу `ANBOX Slides` и не определяют Studio Core.

## Принцип

ANBOX выглядит как студия, которая проектирует системы, а не как набор сайтов из одного шаблона.

Единство создают:

- узнаваемый кириллический display в H1 HERO и дисциплинированная типографика Onest на остальной странице;
- строгая сеточная дисциплина;
- ясный интерфейсный текст;
- реальные кейсы и материальные визуалы;
- точные контрастные сигналы;
- содержательная, а не декоративная интерактивность;
- общий брендовый уровень `ANBOX STUDIO`.

Различие создают продукт, аудитория, кейсы и локальная арт-дирекция направления.

## Базовая геометрия

```css
:root {
  --abx-studio-shell: 1200px;
  --abx-studio-wide-shell: 3328px;
  --abx-studio-gutter: 20px;
  --abx-studio-grid-gap: 20px;
  --abx-studio-fluid-inset: clamp(20px, 6.667vw, 256px);
}

.abx-studio-shell {
  width: min(var(--abx-studio-shell), calc(100% - var(--abx-studio-gutter) * 2));
  margin-inline: auto;
}

.abx-studio-grid {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: var(--abx-studio-grid-gap);
}

.abx-studio-shell--fluid {
  width: min(
    var(--abx-studio-wide-shell),
    calc(100% - var(--abx-studio-fluid-inset) * 2)
  );
  margin-inline: auto;
}
```

Правила:

- `1200px` остаётся опорным desktop master и базой 12-колоночной композиции;
- основной сайт может использовать подтверждённый fluid/4K profile до `3328px` с inset `clamp(20px, 6.667vw, 256px)`, чтобы композиция и motion не схлопывались в узкую полосу на 2K/4K;
- fluid profile не означает равномерное масштабирование: текстовые меры, media, высота секций и motion limits сохраняют собственные ограничения;
- базовый gutter и column gap: `20px`;
- секции имеют высоту от контента;
- hero может быть крупным, но обязан показывать продолжение страницы или ясный маршрут;
- фиксированные `1560 × 700` экраны не являются core-паттерном;
- на mobile сетка перестраивается по задаче, без горизонтального скролла основного контента.

## Типографика

### Display HERO

```css
@font-face {
  font-family: "ANBOX Display";
  src: url("FONT_PATH/bebas-neue-bold.woff") format("woff");
  font-weight: 700;
  font-display: swap;
}
```

Использование:

- только H1 внутри HERO;
- uppercase-кириллица;
- плотный line-height, проверенный отдельно на `1440`, `390` и `320px`;
- не использовать для H2–H6, названий секций, карточек, кейсов, перебивок, CTA, дат и латиницы.

### UI и основной текст

```css
--abx-font-ui: "Onest", Arial, sans-serif;
```

Onest используется для:

- всех заголовков после HERO: H2–H6, названий секций, карточек и кейсов;
- навигации и CTA;
- основного текста;
- дат, цен, чисел и латиницы;
- подписей, форм и интерфейсных состояний.

Не называть Evolventa или публичный `Bebas Neue Regular` точным студийным display-файлом.

## Цвет

### Core anchors

```css
:root {
  --abx-studio-purple: #ad95ee;
  --abx-studio-purple-strong: #7658d0;
  --abx-studio-purple-soft: #ded4f7;
  --abx-studio-purple-highlight-dark: rgba(173, 149, 238, 0.48);
  --abx-studio-lime: #dde63f;
  --abx-studio-ink: #151716;
  --abx-studio-paper: #f3f4f0;
  --abx-studio-white: #fff;
  --abx-studio-line: rgba(21, 23, 22, 0.14);
}
```

Роли:

- `purple` — брендовый интерфейсный и навигационный сигнал основного коммерческого сайта;
- `purple-strong` — контрастный текстовый, focus- и accessibility-сигнал там, где `purple` не обеспечивает нужный контраст;
- `purple-soft` и `purple-highlight-dark` — производные одного `purple` для текстового выделения соответственно на светлой и тёмной поверхности; геометрия выделения остаётся общей;
- `lime` — активное действие, короткий маркер или контрастная зона;
- `ink` — основной текст и тёмные смысловые поверхности;
- `paper` — нейтральная рабочая поверхность, на которой кейсы сохраняют собственный цвет;
- `white` — чистая служебная поверхность, в том числе фон подвала основного сайта;
- `line` — структурные границы без тяжёлых теней.

Для основного сайта raw-значения `#9B7CFF`, `#8B67FF`, `#9F8BD8` не создают новые purple-токены: они нормализуются к `purple`; `#7462BD` и `#8F71E6` нормализуются к `purple-strong`. Базовый lime во всех компонентах один — `#DDE63F`; светлые lime-поверхности задаются только как производные `color-mix()`/alpha, а не как новый акцентный цвет.

Core-пара не обязана использоваться в каждом направлении одновременно. Ветка может:

- сохранить оба цвета;
- оставить один брендовый сигнал;
- заменить локальную палитру полностью, сохранив шапку, сетку и типографику;
- передать основной цвет реальным кейсам.

Любое отклонение фиксируется в документе направления.

## Изображения и кейсы

- Кейсы — основной доказательный и цветовой материал студии.
- Не затемнять яркие работы общей декоративной атмосферой без продуктовой причины.
- Крупные изображения, упаковка, фото и видео должны оставаться заменяемыми assets.
- Важный текст не запекается в raster, если его нужно редактировать или индексировать.
- Генеративные изображения не подменяют реальные результаты, документы и продуктовые доказательства.
- Детальные изображения могут использовать отдельный детерминированный мастер поверх генеративного окружения.

## Шапка и связь направлений

Направление должно сохранять видимую связь с `ANBOX STUDIO` через один или несколько элементов:

- бренд в шапке;
- подпись направления;
- общую сетку и типографику;
- переход к другим направлениям;
- общую систему CTA или footer.

При этом название направления и его продуктовая категория должны быть понятны без знания структуры студии.

## Компонентная логика

Core определяет не единственную форму компонентов, а их поведение:

- CTA имеет ясную основную подпись и устойчивую интерактивную зону;
- карточка появляется только там, где действительно нужна группировка;
- кейс может быть крупнее интерфейсного контейнера и задавать ритм секции;
- навигация показывает место пользователя в продукте или направлении;
- формы сообщают следующий человеческий или технический шаг;
- hover никогда не является единственным способом получить информацию.

## Motion

- Страница читается и работает без анимации.
- Одно направление использует ограниченный набор согласованных motion-систем.
- Движение объясняет причинно-следственную связь, состояние или работу материала.
- Кейсы и лица не деформируются декоративным эффектом.
- Поддерживаются `prefers-reduced-motion`, static fallback и mobile-сценарий без hover.
- Тяжёлый эффект останавливается вне viewport и не блокирует критический контент.

## Ветки

| Направление | Что наследует | Что определяет самостоятельно |
|---|---|---|
| ANBOX Studio website | полный Core | контент и актуальная режиссура главного сайта |
| ANBOX Slides | брендовый уровень и качество | slide-card `1560 × 700`, graphite topbar, orange/paper арт-дирекция |
| ANBOX Study | shell, 12 колонок, display + Onest, case-led подход | образовательная палитра, наставнический сценарий и motion упаковки |
| ANBOX Live Tuner | бренд, типографическая дисциплина, QA | интерфейс software-продукта, состояния редактора и модель поставки |
| Motion Library | технические стандарты | каталог эффектов без обязательной визуальной палитры |

## Запрещено

- Сводить ANBOX Studio к презентациям.
- Делать slide-card или graphite topbar обязательными для всех направлений.
- Использовать один и тот же hero во всех продуктах.
- Копировать core purple/lime без определения их роли.
- Строить направление из универсальных SaaS-карточек и случайных градиентов.
- Подменять кейсы декоративными абстракциями.
- Добавлять motion без mobile и reduced-motion сценария.
